## Contracts and examples

`packages/country-rules` validates UA-only rule JSON v1, provenance fields, verification status, IDs and JSON round trips. `source.editionDate` is distinct from optional `source.effectiveDate`; existing effective-date input remains accepted. `verified` still requires a source and explicit reviewer/date/evidence metadata. The validator checks shape, not a person's expertise or legal correctness.

`@traffic-laws/country-rules/traffic-situation` defines a versioned semantic model for intersection layout/control, lanes, intended vehicle maneuvers, sign and signal assignments, authored maneuver permissions, plan-view trajectories, candidate conflicts and candidate simultaneous movement. Additive optional fields now capture explicitly observed road relation, road-user exclusions, main/secondary lane class, signal mode, vehicle type, swept path width and occupancy intervals. The validator rejects unknown fields, duplicate/broken IDs and unsupported values. `allowed`/`prohibited` authored maneuver permissions still require resolved **verified** rules. Neither `candidate` nor `undetermined` simultaneous movement is permission to proceed.

`@traffic-laws/country-rules/traffic-rules-engine` implements the narrow cases in [the design and rule matrix](traffic-rules-engine-design.md): main green/red signal admission, signal-off transition, oncoming yield at a left turn/U-turn on main green, secondary-to-main yield, and right-hand yield at equal unregulated roads. Pairwise priority is not a total order. It compares exact polyline segments and authored swept widths, then authored occupancy intervals; legal yield is a separate stage. Yellow with the 8.11 exception, regulators, trams, pedestrians, other active users, extra signal sections, blocked exits, turning main roads, roundabouts, missing facts and conflicting facts are unresolved or unsupported. Without a verified source, `certainty` is `unsupported` even if `technicalCertainty` is `determinate`. Synthetic reviewed fixtures in tests exercise software branches only.

`packages/scenarios` retains strict ticket JSON v1, optional validated Scene Definition snapshots, rule-reference resolution, and local review/publish gates. Optional `trafficDecision` binds a machine-checkable claim and formal situation to a ticket. Validation rejects a contradictory correct answer, engine claim, source trace, provision mention or bound scene vehicle, signal or sign. A new preset-specific consistency check also rejects incompatible object approach/heading, vehicle-path start/exit, and bound sign/signal position/orientation. Text-only tickets continue without the engine. The original two scene-data demos remain drafts. Three Ukrainian tickets in `education-demo.ts` cover a red signal, a left turn on main green, and an unregulated main/secondary-road intersection. They reuse copies of the existing urban preset. All three remain `in_review` and cannot transition to verified/published locally. The development-only Web route now lists unconfirmed scene facts; production exposes no ticket feed.

Production has no feed. No current ticket is safe for production publication. Full PDR coverage is likewise incremental later scope; unsupported cases remain diagnostic here.
