# Архитектура

## Как устроен проект

Это pnpm workspace с одним приложением `apps/studio`. Turborepo запускает задачи пакетов и кеширует сборки, lint и тесты. Он не является дополнительным сервером или приложением.

Раньше Next.js-приложение находилось в корне и использовало npm. Теперь в корне находятся только управление репозиторием, документация и общие настройки. Приложение перенесено целиком: извлечение 3D-кода в пакеты сейчас не требуется.

## Studio

- `src/app` содержит единственную страницу и layout Next.js App Router.
- `src/components/layout` — оболочка интерфейса.
- `src/components/debug` — панели Studio, инспектор и статистика.
- `src/components/scene` — сцена React Three Fiber, модели, материалы, дорога и камера.
- `src/stores/useStudioStore.ts` — Zustand: выбранный объект, слои, камера, сигналы, настройки и метрики.
- `src/lib` — каталоги объектов, параметры дороги и расчёт габаритов.
- `src/types/studio.ts` — типы транспорта, камеры, слоёв, инспектора и метрик.
- `scripts/previewVehicles.ts` внутри приложения — технический CPU-рендер для проверки геометрии.

Сцена загружается на клиенте. Все модели процедурные, надписи используют Canvas-атлас; внешние модели, HDRI и текстуры не скачиваются. Режим demand, ограничитель кадров и остановка на скрытой вкладке остаются прежними.

## Правила зависимостей

Приложение может использовать общий пакет из `packages`, когда он действительно понадобится. Общий пакет не должен импортировать приложение. Приложения не должны напрямую импортировать исходники друг друга.

Пока общих runtime-пакетов нет: не нужно создавать их ради структуры. Первый критерий извлечения — конкретный второй потребитель, понятные входы и выходы, независимость от Zustand Studio.

Алиас `@/*` относится только к `apps/studio/src/*`. Пути между приложениями через этот алиас не добавляются. Каждая используемая внешняя библиотека объявляется в package.json своего потребителя.

## Общие настройки

`tooling/typescript/base.json` включает `strict: true`. Studio расширяет базу Next.js-настройками, JSX, алиасом и путями сгенерированных типов.

`tooling/eslint/next.mjs` содержит общий профиль ESLint для Next.js. Корневой ESLint проверяет инфраструктурные скрипты, приложение — собственный код. Prettier настраивается единственным `prettier.config.mjs`.

На время архитектурной миграции прежние `src` и скрипт превью исключены из массового Prettier-форматирования: они сохранены побайтно. Их ESLint и TypeScript продолжают проверять. Форматирование старого кода можно вынести в отдельное изменение.

## География

Первая версия обучает исключительно украинским ПДД. Когда появится образовательный контент, юрисдикция должна быть явным атрибутом его набора, например `countryCode: "UA"`, а версия правил — отдельным атрибутом.

Геометрия и отображение 3D не должны определять юридическую правильность ответа. Для будущего второго рынка потребуется отдельный набор правил и контента, а не копия Studio. На Фазе 1 нет регионального runtime, иностранных правил, билетов, API или базы данных.

## Ограничения текущего этапа

Один Zustand store удобен для Studio, но его не следует превращать в глобальное состояние всей образовательной платформы. Типы Studio описывают инструменты просмотра, а не экзаменационную предметную область.

Генератор `vehicles/assetBuilder.ts` используется также окружением. Это существующая связь, её не меняли. При реальном выделении общей 3D-библиотеки он может стать её внутренней утилитой.

Путь `apps/studio/out` относится только к статическому экспорту Studio. Решения о серверном приложении, авторизации и хранении данных принимаются отдельно на следующих фазах.
