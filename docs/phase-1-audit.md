# Фаза 1: аудит и основа monorepo

Дата проверки: 16 октября 2026 года.

## Результат

Единственное существующее приложение перенесено в `apps/studio`. Настроены pnpm
Workspaces, Turborepo, общий строгий TypeScript, ESLint, Prettier и корневые команды.
Новые приложения, backend, учебные билеты и региональный контент не создавались.
Все 42 исходных файла из `src/` и `scripts/` сохранены побайтово относительно Git HEAD.
Модели, интерфейс, камеры, освещение и состояние Studio не изменены.

## Архитектура до изменений

- Одно Next.js-приложение в корне, npm и `package-lock.json`.
- App Router, статический экспорт `output: "export"`, неоптимизируемые изображения.
- Turbopack для разработки, webpack для production build.
- React Three Fiber и Drei; процедурные модели Three.js, общие геометрии и материалы.
- Надписи автомобилей создаются через Canvas; внешних GLB, HDRI и файлов текстур нет.
- Один Zustand store для Studio; типы находятся в `src/types/studio.ts`.
- Локальный alias `@/*` указывает на `src/*`; Vitest проверяет геометрию, сцену и store.

## Обнаруженные проблемы и риски

1. `three-stdlib` и `sharp` импортировались без прямого объявления. Исправлено:
   pnpm не должен зависеть от случайного npm hoisting.
2. Команда production-запуска не соответствовала статическому экспорту. Исправлено
   в scripts и документации; серверное приложение не добавлялось.
3. Локальных циклов импортов и необъявленных импортируемых пакетов не обнаружено.
   Новый AST-аудит проверяет 41 TS/TSX-файл, включая скрипт превью, и учитывает alias.
   Он не проверяет внутренние циклы сторонних пакетов и вычисляемые runtime-импорты.
4. Кандидатов на неиспользуемые runtime-зависимости не найдено. `react-dom` нужен
   Next.js, хотя приложение не импортирует его напрямую. Инструменты разработки
   дополнительно проверены по конфигурациям и scripts; автоматический аудит импортов
   не является доказательством отсутствия любых неиспользуемых dev-зависимостей.
5. `vehicles/assetBuilder.ts` используется и окружением. Сейчас это рабочая локальная
   зависимость; выделять общий модуль стоит отдельно при появлении второго потребителя.
6. Zustand store относится только к Studio. Не превращать его в глобальное состояние
   будущих приложений. Типы сцены пока также остаются локальными.
7. Общие кэши ресурсов Three.js рассчитаны на срок жизни приложения. При будущей
   динамической загрузке ресурсов понадобится отдельная политика освобождения памяти.
8. Скрипт превью использует `/private/tmp`: это существующее ограничение macOS.
   Для Linux CI потребуется отдельное изменение на системный временный каталог.
9. ESLint 9.39.5 выдаёт предупреждение об устаревании. Обновление major отложено до
   отдельной проверки совместимости Next ESLint и TypeScript.
10. pnpm блокирует install script `unrs-resolver@1.12.2`; lint при этом проходит.
    Разрешены только необходимые build scripts `esbuild` и `sharp`. Новые разрешения
    не следует добавлять автоматически без проверки на целевой платформе.
11. Prettier намеренно не переформатирует прежние `src/`, скрипт превью и исторические
    документы. Массовое форматирование должно быть отдельным изменением.

и FPS не выполнены — доступа к браузеру не было. CPU-превью, HTTP-проверки и тесты
не заменяют такую проверку и не доказывают отсутствие любых runtime-проблем GPU.

`/private/tmp/traffic-laws-phase1.2GBG41/`. Там находятся старые `node_modules`,

- Для первого рынка использовать только украинские ПДД и проверяемые официальные

- Выделять общие пакеты только при реальном повторном использовании, не переносить
  туда весь Studio store или все типы сцены заранее.
- Добавить CI с frozen lockfile и браузерную smoke-проверку WebGL на целевой платформе.
- Отдельно запланировать обновление ESLint и переносимость скрипта превью.
