# 3D Asset Library

`@traffic-laws/assets-3d` — единственный владелец процедурных моделей и GPU-ресурсов.
Studio использует библиотеку через небольшие адаптеры; Web — через отдельную dev-проверку.
Пакет не импортирует Next.js, Zustand, UI или файлы приложений. Версии зависимостей при переносе не менялись.

## Что существует

- `vehicles`: седан, SUV, мотоцикл с водителем, скорая, полиция, пожарная машина;
- `characters`: четыре статических персонажа;
- `environment`: четыре здания, instanced-озеленение и комплект лавок/фонарей;
- `roads`: существующее городское перекрёстное полотно, разметка и геометрические функции;
- `signs`: уступить дорогу, главная дорога, STOP;
- `traffic-lights`: трёхсекционный светофор с сигналом через props;
- `resources.ts`, `Primitives.tsx`, `AssetParts.tsx`, `vehicles/assetBuilder.ts`: общие материалы,
  геометрия, instancing и процедурная сборка;
- `registry`: 21 запись, измерения и соответствующие компоненты; `types`: независимые типы.

Имена существующих модулей сохранены для проверяемого переноса. Пустые каталоги не созданы.
Сельские дороги, автомагистрали, железнодорожные переезды и новая спецтехника — будущее расширение.
Озеленение и мебель пока являются комплектами с исходными координатами, а не каталогом отдельных
деревьев/скамеек: разделение изменило бы batching и требует отдельного измерения производительности.

## Координаты и ресурсы

Единицы — метры, система правосторонняя: Y вверх, X поперёк, +Z вперёд у транспорта.
Знаки и фасады смотрят в +Z; у недирекционных комплектов это только ось отсчёта.
Масштаб по умолчанию `[1, 1, 1]`. Положение и поворот в мировой сцене задаёт потребитель.
Транспорт имеет исходную опору около Y=0; здания — локальное основание. Персонажи сохраняют
исходные небольшие зазоры у обуви, дорога содержит основание ниже Y=0, а окружение уже учитывает
высоту тротуара. Перенос не нормализует эти различия автоматически.

`boundingBox` описывает фактическую геометрию в локальных координатах, `dimensions` — размер X/Y/Z
включая зеркала, козырьки, водителя и другие выступы. Для размещения нижней точки точно на поверхности
используйте смещение `surfaceY - boundingBox.min[1]`; для дороги опорная поверхность — асфальт Y=0,
а не низ основания. Для моделей транспорта +Z задаёт направление движения; attachment к точному
элементу требует явной точки из исходной геометрии, не догадки по каталожной длине Studio.

Материалы принадлежат библиотеке: используйте ключ `MaterialName` и существующий `material`.
Не меняйте общий материал в одном экземпляре без понимания влияния на остальные модели.
Геометрии, материалы, объединённые части и Canvas-атлас надписей — намеренные кеши на время жизни
модуля. Они используют `dispose={null}`, чтобы размонтирование одного экземпляра не разрушало другой.
Временные геометрии после объединения освобождаются; `Batch` освобождает собственный InstancedMesh.
Новые динамические ресурсы должен освобождать их владелец. Не добавляйте аллокации и React setState
в кадровый цикл. `readAnimation` позволяет читать актуальные флаги без подписки всей модели на store.

## Реестр и происхождение

```tsx
import { ASSET_REGISTRY } from "@traffic-laws/assets-3d/registry";
import { VehicleModel } from "@traffic-laws/assets-3d/vehicles/VehicleModel";
// Внутри Canvas:
<VehicleModel kind="sedan" />;
```

`/registry` содержит только метаданные и не создаёт Three.js-ресурсы. `/models` — полный набор
компонентов по стабильным ID, предназначенный для инспекции; для одного объекта используйте узкий
export. Модуль транспорта пока создаёт общий существующий кеш шести машин; разделение кеша по моделям
не входит в архитектурный перенос. Корневой export — удобный общий API, не обещание минимального чанка.

В каждой записи есть версия, описание, категория, UA-совместимость текущего проекта, масштаб, оси,
источник, лицензия, bounding box, размеры и производительность. UA не означает юридическую
сертификацию ливреи или знака. В репозитории не найдена отдельная лицензия ассетов, поэтому статус
`unspecified` записан явно; лицензия для внешнего распространения требует решения владельца.
Все модели процедурные; внешние ассеты не добавлены.

Размеры и числа полигонов получены R3F test renderer, а не оценены вручную. Измерения включают
скрытые лампы, но не кольцо выделения Studio. `drawCalls`, `fps`, `frameTimeMs` равны `null`, пока
нет измерения настоящего WebGL-рендера. Количество mesh нельзя выдавать за draw calls:
проходы теней, видимость и instancing меняют результат.

## Как добавить автомобиль: для начинающего разработчика

1. Добавьте процедурную модель в `src/vehicles`, используя `AssetBuilder`, общие материалы и
   существующий wheel layout. Не копируйте геометрию в приложение. Сохраните +Z вперёд и метры.
2. Для нового вида расширьте `VehicleKind` и `VEHICLE_GEOMETRY`; если это другой интерфейс модели,
   экспортируйте самостоятельный типизированный компонент через `package.json`.
3. Добавьте уникальный ID и описание в `registry/definitions.ts`, компонент — в `registry/models.tsx`.
   Не регистрируйте отсутствующие модели. Зафиксируйте реальный источник и условия лицензии.
4. Обновите измерения и проверьте diff; это принятие новой геометрии, а не способ скрыть регрессию:

   ```sh
   UPDATE_ASSET_MEASUREMENTS=1 pnpm --filter @traffic-laws/assets-3d test --run src/registry/measurements.test.tsx
   pnpm exec prettier --write packages/assets-3d/src/registry/measurements.json
   pnpm test
   ```

5. Добавьте размещение в `apps/studio/src/lib/sceneAssets.ts` (для транспорта — `studioConfig.ts`)
   и соответствие ID в `assetLibrary.ts`. При новом типе добавьте небольшой адаптер в `SceneObjects`.
   Откройте `pnpm dev:studio`, раздел **Бібліотека 3D**, найдите модель и нажмите её имя.
   Каталог открывает существующий изолированный Preview и Object Inspector.
6. Web-проверка находится в `apps/web/src/app/dev/assets-3d`: `pnpm dev:web`, затем
   `http://localhost:3000/dev/assets-3d`. Модель загружается через `next/dynamic`, `ssr:false`.
   Production возвращает 404, а условие вокруг dynamic import исключает 3D-чанк из сборки.
7. Выполните `pnpm check`. Для геометрического отчёта:

   ```sh
   STUDIO_ASSET_REPORT=1 pnpm --filter @traffic-laws/studio test
   ```

   Сравните тот же ракурс, качество, размер окна, FPS, frame time, draw calls и память в панели
   Studio. Сравните размер `.next/static` до/после сборки. CPU-превью не заменяет GPU-проверку.

## Границы этапа

Пакет не содержит Scene Composer, физики движения, учебных правил, backend или контента новых стран.
Выбор объектов, кольцо выделения, камера, освещение, качество, adaptive DPR и Zustand остаются в Studio.
Старые пути Studio для ресурсов — только re-export, не вторые реализации.
Текущие границы и ограничения: [архитектура](../../docs/ARCHITECTURE.md) и
[аудит](../../docs/AUDIT.md).
